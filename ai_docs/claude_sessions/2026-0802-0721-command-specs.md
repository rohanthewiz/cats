# Phase 0.5 — the command table as data

## What it is

The name ↔ params ↔ result mapping for the 47 §7 commands lived only in the
`Dispatch` switch and the doc comments beside each params struct — readable, but
not walkable by a program. `CommandSpec` turns it into a table
(`internal/app/command_vocab.go`), which is what `cmd/catgen-dart` will emit the
mobile client's typed call sites from in Phase 1.

```go
type CommandSpec struct {
	Name           string
	Params         any  // zero value of the params struct; nil when parameterless
	Result         any  // zero value of CmdResult.Data; nil when nothing is returned
	ReplyRequired  bool // Dispatch silently drops it when the caller can't receive a result
	ParamsRequired bool // absent params fail with "bad params" rather than decoding to zero
}
```

`Params`/`Result` hold a **zero value of the struct**, not a `reflect.Type` — the
table stays readable at the call site and a generator takes `reflect.TypeOf`
itself. `nil` is load-bearing in both: "takes no params" and "returns no data"
are distinct from "takes an empty struct", because a generator emits different
signatures for them.

`CommandNames()` is now derived from the table, so names and shapes cannot
disagree. Order is byte-for-byte what `catctl commands` printed before (verified
by diffing the constant sequence out of `git show HEAD:` against the new one, and
by running the built binary: 47 lines, same order).

## `ParamsRequired` — the field the plan did not have

The plan specified four fields. The fifth exists because optionality is a
property of the **command**, not of the params type, and a generator reading only
the type would get it wrong:

- `WorkspaceParams` is **required** by `workspace.focus`, which cannot guess an id.
- The same struct is **optional** for `workspace.close`, where an empty id means
  the active workspace.

Same split shows up in `OptPaneParams` vs `PaneParams` — but that pair is at
least visibly two types. `WorkspaceParams` is one type on both sides of the line.

## Two corrections to the plan's stated facts

- **`worktree.list` is `ReplyRequired` too.** The plan named seven commands
  (`capture`/`read`/`wait`/`path.list`/`config.get`/`theme.list`/`plugin.list`);
  the code has eight — `worktree.list` takes the same `!r.WantsReply() → return`
  early exit. The flag is defined as exactly that set, so it follows the source.
- **The config/theme writers return `ConfigGetResult`, not nothing.**
  `config.set`, `theme.save` and `theme.delete` each end in
  `r.OK(o.configSnapshot())` — they echo the same snapshot a read returns, so a
  client refreshes from the reply it already has instead of following up with
  `config.get`.

### The four sweeps (`internal/app/command_vocab_test.go`, new)

| Test | Claim |
|---|---|
| `TestCommandSpecsRouted` | parses the **Dispatch switch's own AST**: constants, table and cases must agree in every direction |
| `TestCommandSpecsParamsRequired` | a no-params dispatch fails with `bad params` **iff** the flag says so |
| `TestCommandSpecsReplyRequired` | given a `WantsReply()==false` responder, exactly the flagged commands do *nothing* — no backend effect, no reply, no pending registered |
| `TestCommandSpecsResultTypes` | the returned value's type equals the declared one |

Plus `TestCommandSpecsShape` (Params/Result must be a struct value or nil;
`ReplyRequired` implies a `Result`) and `TestCommandSpecsCopyAndNames`
(`CommandSpecs()` hands out a clone — a caller sorting it must not reorder the
vocabulary for the process).

### Why the AST test earns its ~60 lines

`TestCommandNamesAllRouted` dispatches every enumerated name and rejects the
"not supported yet" fall-through. That is one direction only. **A command added
to the switch but never listed was invisible**: absent from `catctl commands`,
absent from every generated client, and no test failing. Only reading the switch
closes that side, and a dispatch cannot show it.

It resolves each `case` identifier through the const block's own
`CmdX = "wire.name"` pairs, so the test never re-lists a wire string — a rename
propagates instead of breaking the guard.

`TestCommandNamesAllRouted` also gained an unknown-command case. Without it, a
default clause that stopped saying "not supported yet" would make the whole sweep
vacuous while still passing.

### Neutering

Each guard was neutered to confirm it bites, and each failed exactly one test,

The result-type sweep carries a floor (`checked < 8`): raising it to 100
reported "only 9 result types were actually compared", proving the counter is

### The limit, stated

The sweep reaches **9** result types — the ones the fakes carry to completion
(the queries, `tab.create`, `workspace.create`, and the `config.get`/`theme.list`
the fake backend answers inline). The rest are produced asynchronously by
`cmd/catway` and were audited by **reading every `r.OK` call there**, not by
execution:

- `read`/`capture` resolve through `resolvePending` with
  `browserproto.ReadResult`/`CaptureResult` — aliases of the `app` types.
- `worktree.*`, `plugin.*`, `path.list`, the config/theme writers — each checked
  against its literal.

The test comment says so rather than implying coverage it does not have.

## Deliberately not done

- **No `catctl commands --json`.** A machine-readable dump would be scope creep:
  `catgen-dart` lives in this repo and imports `internal/app` directly, so
  nothing needs the table over a pipe.
- **No `CommandSpecFor(name)`.** Nothing uses it yet. The natural first caller is
  `catctl help <raw method>`, which today prints only "a raw §7 command" and
  could print the params struct's JSON keys — a real improvement, but a different
  change.
- **No `browserproto` re-export.** The browser has no use for the table.
