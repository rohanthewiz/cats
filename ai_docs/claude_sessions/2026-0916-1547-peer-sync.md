# Peer sync: reconciling two cats backends (workspaces, todos, plugins)

*Two cats instances can now sync their backends — the state of record, not
the screen. A new `internal/peersync` package plus `/peer/v1/*` routes on
catway let one instance dial another, exchange a bundle, and each apply what
it lacked: workspaces where the same folder exists, cats-todo backlogs merged
row by row, plugins re-installed from their recorded source. Every sync ends
with a report that lists what did not sync and why. Nothing is ever deleted
or overwritten in either direction.*

## 1. What existed, and what did not

A survey of the repo (subagent + direct reads) settled the shape:

- **No peer, relay or replication code existed.** `hosts:` are cathost
  terminal daemons attached to one catway — a different thing. The relay in
  `ai_docs/mac-app-and-remote-relay-plan.md` was never built.
- **Three stores, three identities.** Workspaces live in `session.json` with
  process-local ids (`w1`…) but a stable `identity_cwd`; plugins are dirs
  under `~/.config/cats/plugins/<id>` each with a `.cats-plugin-source.json`
  `{source,url,ref}`; todos are cats-todo's JSON arrays at
  `<project>/.cats-todo/todos.json` and `~/.config/cats-todo/todos.json`,
  which cats had **no code for at all** (cats-todo is `package main`).
- **The HTTP surface is tiny** (`/login`, `/`, notify callback, `/ws`);
  everything else is a §7 command over `/ws`. The auth guard accepts the
  shared secret as a bearer token, which is what a peer can present.
- cats-todo already has a LAN bundle protocol (`peer.go`, `bundle.go`) whose
  rules were borrowed: dedupe on title+prompt, strip schedules, attachment
  names reduced to safe relative paths, sizes capped.

## 2. Design

```
initiator                                   peer
   │  GET  /peer/v1/bundle?want=…             │
   │ ────────────────────────────────────────▶│  Collect
   │ ◀──────────────────── Bundle (theirs) ───│
   │  Apply(theirs) here        ← "pull"      │
   │  POST /peer/v1/apply  Bundle (mine)      │
   │ ────────────────────────────────────────▶│  Apply(mine) there ← "push"
   │ ◀────────────────────── ApplyReport ─────│
   SyncReport = pulled + pushed
```

Decisions, each a deliberate refusal:

| Store | Identity | Does | Never does |
|---|---|---|---|
| workspaces | `identity_cwd`, home dir translated (`/Users/x/…` ↔ `/home/x/…`) | creates where the folder exists; **asleep**, active workspace untouched | creates folders, moves panes, closes anything; remote-host workspaces neither offered nor matched |
| todos | row `id`, then title+prompt | adds missing rows, propagates completion (done/frozen beats open), copies attachments, creates a project backlog where the folder exists but has none | overwrites a row that differs (kept, reported as conflict — rows carry no mtime); carries a schedule; resurrects a done row |
| plugins | install source + ref | `plugin.Install` for what is missing, build output tail in the report | updates a plugin on both sides; installs linked or broken ones |

- **Todo rows are `map[string]any`**, never cats-todo's struct, so unknown
  fields round-trip and cats stays decoupled from cats-todo's schema.
- **Trust = the existing secret.** The `/peer/v1` routes sit behind the
  normal guard; no second permission, by the same argument
  `config.Host.ControlRelay` makes (a caller with `/ws` can already type into
  any shell). `https://` self-signed peers are pinned by fingerprint; `http://`
  is confined to loopback.
- **A sync that cannot run is still a report** (`error` set, items empty):
  the caller is about to show one, and "could not connect" is its first line.

## 3. What was added

- `internal/peersync/` — `peersync.go` (Bundle, Want, path translation),
  `todos.go` (backlog I/O, generic merge, attachment safety), `plugins.go`,
  `client.go` (bearer + pin, no redirect following, 96 MiB cap), `sync.go`
  (`Local` seam, Collect/Apply/Sync), `report.go` (statuses, `Render`).
- `internal/gwtls/client.go` — `ClientConfig(serverName, fingerprint)`,
  the pinning rule shared with the cathost dialer.
- `internal/config` — `Peers []Peer`, `validatePeers`, `ValidatePeerURL`.
- `wire/vocab.go` — `peer.list/sync/attach/detach` + params/results;
  `internal/app` — dispatcher cases, four `Backend` methods, recorder
  classes, test fake.
- `cmd/catway/peers.go` — `peerLocal` (hops onto the loop via `onLoop`;
  new workspaces created, renamed, slept, previous focus restored, one
  `ApplyModel`), the `Start*`/roster methods (config saved like
  `HostAttach`), the three rweb handlers; routes registered in `main.go`.
- `cmd/catctl` — `peers`, `sync <peer> [workspaces|todos|plugins|all] [pull|push|both]`
  (every category typed on purpose; exit 1 on unreachable/failed, 0 on
  skipped), `attach-peer <id> <url> [token_file] [label…]`, `detach-peer`;
  the report prints its rendered lines.
- Web: `43-peers.js` (roster, sync dialog with three checkboxes + direction,
  report view with copy), `30-peers.css`, palette + gear entries;
  `42-boot.js` → `44-boot.js` so the asset list stays in filename order.
- Docs: `docs/subsystems/peer-sync.md` (+ nav), config / CLI / control-API
  references, `config.example.yaml` `peers:` block.

## 4. Verification

- Unit tests: translation, merge rules (idempotent second merge), attachment
  traversal refusal, apply against a fake `Local`, want/schema gating,
  render, httptest round trip incl. bad token and redirect.
- `go test ./...` and `go test -tags ghostty ./...` green; vet, gofmt, and a
  `node --check` of the assembled JS bundle.
- **Live smoke test**: two cathost+catway pairs on `127.0.0.1:9431/9432`,
  isolated by `CATS_CONFIG`, `CATS_PLUGINS_DIR`, `CATS_TODO_CONFIG_DIR`,
  peer token files, a local git repo as a plugin source. `catctl sync b all`
  from A: workspace `two` arrived on A asleep, `p1` on B asleep, the
  vanished-folder workspace `ghost` reported *skipped — no such folder*,
  global backlogs unioned with the done row propagating, `smoke.hello`
  installed on B. Second run: all unchanged. Unknown peer → exit 1.
  (Recipe saved to memory as `two-catways-smoke-test`.)
- **Bug found by the smoke test**: a wrong credential produced
  `decode: invalid character '<'` — the guard's 302 to `/login` was being
  followed. Fixed with `CheckRedirect: ErrUseLastResponse`; a redirect now
  reads "the peer refused the credential", covered by a test.
