# Phase 0.6 — device pairing

## What it is

A phone needs a credential. Handing it the shared password is an escalation the
plan rejects up front: any local process can read the control socket — a plugin,
a `curl | sh` postinstall, one of the coding agents this machine exists to run —
and a password reaches catway from anywhere on the network, forever, with no
revocation short of a restart. Worse, `catctl pair` run *inside a cats pane* has
its output swept into `~/.local/state/cats/history.json`, writing to disk the one
secret `internal/gwauth` promises never touches it.

So the socket mints a **grant** instead:

```
catctl pair ──socket──▶ IssuePairToken ──▶ token (5 min, single use)
                                            │
              QR / cats:// URI ──▶ phone ───┘
                                     │
                                     ▼
          POST /login password=<token> ──▶ RedeemPairToken ──▶ session
```

| | Grant | Shared password |
|---|---|---|
| Lifetime | `gwauth.PairTTL`, 5 min | forever |
| Uses | exactly one | unlimited |
| What it buys | a session credential | full access |
| Revoked by | redemption, expiry, restart | changing it and restarting |

What the device ends up holding is an *ordinary session*: signed with the
per-process key, bounded by `session_ttl`, killed by a restart. That
revocability is the whole argument — it is exactly the property the password
lacks, and the reason a long-lived derived device token would have been the wrong
answer (permanent, no revocation short of a restart — the thing being rejected).

## The pieces

| Where | What |
|---|---|

| `cmd/catway/auth.go` | the one `\|\|` in the login check; a session value accepted as a bearer |
| `cmd/catctl/pair.go` | QR render, `cats://pair?…` link, `--json` for scripting |

## The security boundary is a placement, not a check

`pair` is answered in `orch.controlDispatch` **before** the dispatch is posted
onto the loop, so it never reaches `app.Dispatcher`:

```
browser  ──ws cmd──▶ app.Dispatcher ──▶ §7 command table   ← no pairing here
catctl   ──unix───▶ controlDispatch ──┬─▶ app.Dispatcher
                                      └─▶ handlePair       ← owner-only socket
```

A §7 command is reachable from *both* front ends by construction. Minting
credentials from the browser would turn a stolen session cookie — which expires,
and dies with the process — into a permanent second credential. Keeping `pair`
off that table is the containment.

`TestControlDispatchAnswersPairWithoutTheDispatcher` measures this directly: it
gives the orch a buffered mailbox, calls `controlDispatch("pair")`, and asserts
**zero** closures were posted — then calls `pane.list` and asserts exactly one,
so the first assertion is measuring the intercept and not an inert mailbox.

`TestTransportMethodsDoNotShadowCommands` guards the other side: `ping`,
`events.subscribe` and `pair` must never appear in `app.CommandNames()`, or a §7
command of that name would be silently unreachable from the socket.

## Three additions beyond the plan's letter

The plan specified "two functions in `gwauth`, one `||` in `handleLoginPost`".
That is the core, and it is what shipped — but it does not by itself reach a
*native* client.

- **`gwtls.Fingerprint`.** The grant carries the served certificate's SHA-256.
  Over the **DER, not the SPKI**: `gwtls.generate` mints a fresh ECDSA key on
  every regeneration, so SPKI pinning would survive nothing DER pinning does not,
  and the DER hash is the value `openssl` and every browser's cert viewer show.
  A device pins out-of-band at the moment it first learns the address, rather
  than trusting whatever it is handed on a later connection. Phase 2's
  passthrough relay needs exactly this.
- **JSON login + bearer-session.** Phase 1's connection layer sends
  `Authorization: Bearer <stored token>`. Without these two the "device
  credential" is unreachable: a native client would have to scrape `Set-Cookie`
  out of a 303 and it has no cookie jar. `authed()` now accepts a session value
  in that header — which grants nothing new, since the same value is already
  accepted from the cookie and `ValidSession` still bounds it by signature and
  expiry.
- **`authorizeLogin` extracted.** rweb's `Server.Request` synthetic-request helper
  **ignores its `body` argument entirely** (`Server.go:571-576`), so a form POST
  cannot be driven through the handler at all. The security decision moved into a
  pure function; what is left in `handleLoginPost` is the choice between a cookie
  and a JSON body, and `wantsJSON` now takes the header string rather than a
  `rweb.Context` so it is testable too.

## Why an in-repo QR encoder

The plan offered "a small pure-Go encoder — or plain URL text if that dep is
unwelcome against the 6-dep budget". Asked; answer was **in-repo encoder**. Deps
stay at 6, and the alternative — retyping a 141-character URI on a phone keyboard
— defeats the convenience the whole flow is chasing.

`internal/qr` is ~800 lines across four files: GF(256)/Reed-Solomon, the block
table, matrix construction, masking, and a half-block terminal renderer.
Deliberately absent: numeric/alphanumeric/kanji modes (a URI is neither), EC
levels L/Q/H, versions above 10, and any form of decoding.

**Polarity is the thing to get right, not aesthetics.** iOS's built-in scanner is
unreliable on inverted codes. The coloured render sets an explicit
foreground/background pair per cell so dark modules are black on any terminal
theme; the uncoloured fallback (piped output, `NO_COLOR`) draws light modules as
ink, which is correct on a dark background and stated as such.

### Neutering — and the one that got away

Nine guards neutered; **eight failed immediately**:

| neutered | failure |
|---|---|
| dropped the pair-token `\|\|` in `handleLoginPost` | `redeeming the grant did not grant a session` |
| made a pair token reusable | `token is not single-use` (+ the concurrency test) |
| removed the `controlDispatch` intercept | `pair was not answered inline` |
| one wrong EC count in the v9 block table | `v9: 182 data + 5×20 EC = 282, table says 292` |
| wrong reduction polynomial (0x11B, AES's) | `gfExp[gfLog[3]] = 1` |
| dropped the mask from the format bits | `mode indicator 0001, want byte mode` |
| alignment pattern one module wide | `v7: timing pattern breaks at 20` |

**The ninth passed**, and it mattered: removing the zigzag's column-6 skip
changed the encoder's fill path while the test decoder kept the correct one — and
the round trip was still clean.

The reason is structural. Data codewords occupy the *start* of the interleaved
stream and therefore the **right-hand** side of the matrix; EC codewords fill
everything to the left. Reading only the payload back left roughly half the
modules — including every module in the left-most columns — unverified. A fault
confined to that half round-trips perfectly and produces a symbol no real scanner
can read.

Fixed by having `decodeSymbol` de-interleave the EC codewords too and divide each
reconstructed block by the generator polynomial — a Reed-Solomon codeword is a
multiple of it, so this catches any misplacement without needing to know the
right answer. Both the column-6 neuter and an interleave-order swap now fail with
`error correction does not check out`.

### The QR-capacity drift gate

`TestPairURIFitsAQRCode` fired for real on first run, at a threshold I had
guessed. It now asserts two things instead of one: a typical LAN pairing URI
(141 bytes → v8) stays inside v8, and a 57-character hostname still encodes at
all. The first is the tripwire — a field added to `PairInfo` eats the URL budget,
and the failure mode in a terminal is silent, since the QR is simply replaced by
a fallback message nobody reads.

## Deliberately not done

- **No per-device tokens.** A long-lived credential derived from the password
  would be permanent with no revocation short of a restart — precisely what the
  plan rejects. The session is the credential *because* it expires.
- **No `--host` override on `catctl pair`.** `advertiseURL` picks the first
  non-loopback IPv4 on an interface that is up, and keeps a host the operator
  bound deliberately. Nothing has wanted more yet.
- **No rate limit on `/login`.** Already named in "What is not in the model";
  pairing does not change the exposure.
- **No QR in the web UI.** The browser cannot mint grants — that is the point.

## Not verified

**That a real browser survives the 90 s keepalive window** — open since Phase
0.2, three sessions back. The Chrome extension has not been connected in any of
them. Browsers pong in the network stack and the failure mode would be a visible
reconnect loop rather than breakage, but it is the primary client.

## Two limits, stated in the docs

- **Paired devices are not individually revocable.** `IssueSession` carries no
  identity by design (`gwauth.go:81-87`), so two sessions minted in the same
  second are byte-identical. Granularity is the session TTL and the process.
  Named in `docs/subsystems/auth-and-tls.md` under "What is not in the model".
- **The grant is printed into a terminal** whose scrollback may reach disk. That
  is acceptable *precisely because* it is worth minutes and one use — which the
  password would not be.
