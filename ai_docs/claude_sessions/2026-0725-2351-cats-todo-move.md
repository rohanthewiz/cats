## Goal

Move the `cats-todo` plugin out of `cmd/cats-todo` into its own repository at
https://github.com/rohanthewiz/cats-todo (remote was empty), preserving git
history, and clean the cats repo up behind it.

## What was done

### 1. History-preserving split

- `git subtree split --prefix=cmd/cats-todo -b cats-todo-split` produced a
  branch holding the 6 commits that ever touched the plugin (from the phase-2
  herdr-todo port through the list-header feature).
- Cloned the empty remote to `~/projs/go/cats-todo`, pulled the split branch
  into `main`, deleted the temp branch in cats afterward.

### 2. Standalone module conversion (new repo, commit `b4d5e0f`)

`cmd/cats-todo` imported three cats `internal/` packages, which cannot be
imported across module boundaries. The extraction severs them with client-side
**copies** of just the wire contract:

- `internal/app/command_vocab.go` — the full §7 command vocabulary
  (command names, param/result structs). Removed the server-only pieces that
  dragged in cats' layout engine: `SplitDirection`, `NavDirection`, and the
  unexported `optPaneID` helper. Header comment marks it as a copy to keep in
  lockstep with cats.
- `internal/ctlproto/` — `client.go` + `proto.go` only (the envelope and the
  one-shot client). `server.go`/`stream.go` import `app` and stayed in cats.
- `internal/integration/integration.go` — a sliver holding only
  `CatsPaneIDEnvVar` (`CATS_PANE_ID`).

Other conversion work:

- `go.mod`: module `github.com/rohanthewiz/cats-todo`, go 1.26.0; direct deps
  bubbles / bubbletea / lipgloss / sahilm-fuzzy; `go mod tidy` filled in the rest.
- Imports rewritten `rohanthewiz/cats/internal/...` → `rohanthewiz/cats-todo/internal/...`.
- **Test fix** (`context_test.go`, "resolves the project root above the cwd"):
  the subtest relied on the package sitting two levels below the cats repo
  root; the package dir is now itself a repo root so that assumption broke.
  It now builds a synthetic marker repo (`.git` dir) in a temp dir and
  `t.Chdir`s into a nested subdirectory — exercises the ancestor walk
  regardless of where the module is checked out.
- `cats-plugin.toml` header/comments updated: standalone repo, install via
  `catctl plugin install rohanthewiz/cats-todo`, dev-link via
  `catctl plugin link .`.
- `main.go` doc comment: dropped the stale "cats has no plugin host" line.
- Added `README.md` (derived from the cats README section) and `.gitignore` (`bin/`).

Verified: `go build`, `go vet`, `go test ./...` all pass; the manifest's exact
build command (`sh -c "mkdir -p bin && go build -o bin/cats-todo ."`) produces
a working binary (`cats-todo version` → 0.1.0). Pushed to `origin/main`.

## Ongoing contract

The two repos now share the control protocol **by copy, not by import**. Any
change to cats' §7 command vocabulary, ctlproto envelope shapes, or the
`CATS_PANE_ID` env var must be mirrored into cats-todo's
`internal/{app,ctlproto,integration}` copies. The wire values are the
compatibility contract. (Also recorded in auto-memory as `cats-todo-own-repo`.)
