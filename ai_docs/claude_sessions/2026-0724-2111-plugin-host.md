## Request

"Let's do the optional plugin host" — the piece deferred from phases 1
(`pane.send_input`) and 2 (`cmd/cats-todo`): first-class
`cats plugin install/link/run`, replacing the herdr plugin model
(herdr-plugin.toml manifest, install/link, actions, plugin panes) that
herdr-todo was originally written against.

## Design

The governing call: **the server stays plugin-agnostic** — it never parses a
manifest. herdr ran actions server-side and relayed context into plugin panes
via env blobs; cats-todo already gathers its own context in-process over the
control socket, so the host reduces to (a) directory management offline in the
CLI and (b) one generic server capability: spawn a pane running an argv.

- A plugin = a directory holding `cats-plugin.toml` (same shape as
  herdr-plugin.toml: id/name/version/description/platforms/`[[build]]`/
  `[[actions]]`) + whatever its build produces. herdr's `[[panes]]` table is
  deliberately dropped — a cats action runs its TUI directly in the tab that
  launches it; there is no separate server-run pane entrypoint.
- Plugins root: `~/.config/cats/plugins/<id>/` (config-home chain like
  `config.DefaultPath`; `CATS_PLUGINS_DIR` override for tests/scratch). Real
  dir = installed, symlink = linked.

## What changed

### 1. §7 enabler (`internal/app`, `cmd/catway`, `internal/browserproto`)

- **`tab.create` gained optional `TabCreateParams{Title, Cwd, Command, Env}`**
  (decodeOptional — no params keeps the historical bare-shell behavior).
  Title = what tab.rename would set; Command = argv exec'd as the pane's
  process (same `create_pane.command/args` mechanism as agent resume);
  Cwd/Env apply to the default shell too when Command is absent.
- New **`Backend.StageSpawn(pane, SpawnOverride)`** seam: the dispatcher knows
  the new pane's id from the session *before* ApplyModel realizes the PTY —
  the only window where an override can influence the spawn. catway stores it
  in **`spawnPlans`** (the live-command sibling of `resumePlans`), consumed
  exactly once in `createPane`'s connected branch (a pre-connection create
  keeps the plan for reconcile's retry); stale plans are dropped when a pane
  leaves the model in `syncDaemon`.
- **Every pane env now carries `CATS_CONTROL_SOCKET`** (`o.controlSocket`,
  wired in main next to `hookSocket`, cleared if the control listener fails).
  Previously in-pane automation only found the socket by luck of the default
  `/tmp` path.
- `browserproto/cmd.go` re-exports `TabCreateParams`.
- Tests: `fakeBackend.StageSpawn` (staged map + log entry),
  `TestDispatchTabCreateSpawn` (stage-before-applyModel order, title via
  tab.list, bare create stages nothing, empty `command[0]` rejected).

### 2. `internal/plugin` (new)

- `manifest.go`: `Manifest`/`BuildStep`/`Action`, pelletier/go-toml/v2 (already
  a direct dep). `Validate()` — id doubles as the install dir name, so ids that
  could escape the root (separators, `..`, leading dot) are rejected, not
  sanitized; ≥1 action, unique action ids, non-empty commands.
  `SupportsPlatform` accepts herdr's "macos" and Go's "darwin".
  `min_cats_version` is parsed but **not enforced** (no server version
  constant exists; enforcing against a wrong number would be worse).
- `plugin.go`: `Root()`, `List()` (missing root = empty list; broken entries
  surface with `Err` set instead of vanishing), `Get`, `Uninstall` (symlink →
  remove link only, never the checkout), `ActionArgv` (relative argv[0]
  anchored to the plugin dir — the pane's cwd is the *user's* project).
  Env consts `CATS_PLUGIN_ID` / `CATS_PLUGIN_DIR`.
- `install.go`: `Install(source, ref, out)` — `owner/repo` shorthand → GitHub
  URL (schemes/`git@`/paths pass through), shallow clone (`--branch` for
  branch/tag refs; bare shas unsupported until needed) into a dot-prefixed
  temp dir *inside the root* (same filesystem ⇒ atomic rename; crash leaves
  only an invisible dir), validate, run `[[build]]` steps, write
  `.cats-plugin-source.json` provenance (enables a future `plugin update`;
  `.git` kept for the same reason), rename to `<root>/<id>`. `Link(dir)` —
  validate + build + symlink; re-link of the same checkout is idempotent (and
  re-runs the build — the reason a developer re-links).
- Tests: validation table, platform mapping, source-URL resolution, full link
  lifecycle (build stamp, conflict, list/get/argv/uninstall), install from a
  local `git init` repo (skips without git; `-c user.email` keeps it
  gitconfig-independent), broken-entry listing. macOS gotcha: `t.TempDir()`
  lives behind `/var` → `/private/var`, so linked-dir assertions must
  EvalSymlinks-normalize the expectation.

### 3. `catctl plugin` verb family (`cmd/catctl/plugin.go`)

- `install [--ref] | link | uninstall | list | run <id> [action] | help`,
  modeled on `integration.go` (exit codes 0/1/2), dispatched in main.go
  **before the global-FlagSet re-parse** (the send/run lesson); the
  already-parsed global `--socket` is forwarded for `run`. `--ref` is scanned
  manually to keep the family FlagSet-free.
- `run` = the one online verb: `plugin.Get` → `FindAction` ("" = first
  action) → one `tab.create` call with `{title: action title, cwd: invoking
  dir, command: resolved argv, env: CATS_PLUGIN_ID/CATS_PLUGIN_DIR}` →
  `printResult` shows `{num, pane}`.

### 4. Reference manifest + docs

- **`cmd/cats-todo/cats-plugin.toml`** — cats-todo as the flagship linkable
  plugin (`catctl plugin link ./cmd/cats-todo`; build = `go build -o
  bin/cats-todo .`, resolved from the repo's go.mod). `cmd/cats-todo/bin/`
  gitignored.
- Protocol doc §7: "since added" paragraph for the tab.create params +
